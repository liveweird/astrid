# Documentation Instructions

Maintain the project knowledge base in `knowledge/` and the separate work backlog in `../BACKLOG.md` as the discussion develops. Read `knowledge/working-agreement.md` and the relevant topic notes before updating them.

Capture assumptions, requirements, constraints, open points, questions, decisions, rules, conventions, principles, and tenets. Distinguish user-confirmed requirements and decisions from assistant proposals, working assumptions, and externally sourced facts. Keep consequential decisions and their rationale traceable; mark superseded decisions explicitly.

Use the backlog statuses `[next]`, `[todo]`, `[new]`, `[parked]`, and `[blocked]` according to the working agreement. Record completed work separately from active items. Keep work priorities and dependencies consistent with the knowledge base.

The project remains in discovery. Do not begin application implementation until the user changes that constraint.
